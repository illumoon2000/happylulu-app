# 다우오피스 쓰기 플러그인 준비안

상태: **설계 및 모의 실행 전용**. 2026-10-22, 기준 main `8a4a538`.
실제 자산 예약 API의 endpoint·payload·인증·성공 판정은 확인되지 않았다.
이 문서는 지원되지 않는 API를 추정하거나 실서비스 예약 가능성을 보장하지 않는다.

## 기존 기능과 경계

`docs/PLUGINS.md`, `DaouOfficePlugin`, `DaouOfficeIntegration`의 서버 API 읽기 전용 계약을 그대로 유지한다.
새 `DaouOfficeWritePlugin`은 Foundation만 사용하는 독립 모듈이며 기존 앱의 플러그인 등록·설정·인증 저장소에 연결하지 않는다.
식별자는 `daouoffice-write`, 기본 모드는 비활성이다. 테스트를 위한 명시적인 모의 모드만 있으며 실제 실행 모드는 없다.
기존 읽기 플러그인 사용 설정이나 ChatGPT 로그인으로 쓰기 권한을 활성화하지 않는다.

기능 명세의 HL-PLUGIN-001~003, HL-CAL-001, HL-DAOU-001~004에 해당하는 기존 플러그인 관리·기능 연결·읽기 조회를 보존한다.
새 기능은 **제안 HL-DAOU-WRITE-001 자산 예약 초안**으로 구분한다. 기존 설정 화면(HL-UI-011/014)을 변경하지 않는다.
휴가 예고 PR #56, 붙여넣기 PR #54, 로컬 디자인 작업과 독립적이다. 공개 이슈는 생성하지 않았다.

## 최소 실행 계약

1. 가용성 조회와 예약 명령을 서로 다른 transport protocol로 나눈다. 일반 일정 조회 결과를 자산 가용성으로 해석하지 않는다.
2. 요청은 명시적인 연결/계정 식별자, 자산 식별자, 제목, 시작/종료 절대 시각, 표시 시간대를 갖는다. 자격 정보는 받지 않는다. 비어 있는 식별자·제목, 잘못된 시간대, 과거 시작·종료 역전·유효하지 않은 시각은 거절한다.
3. 준비는 읽기만 수행한다. 조회 오류·충돌·알 수 없는 상태를 가용으로 처리하지 않는다. 가용하면 ID와 짧은 만료 시각을 가진 변경 불가능한 확인용 초안을 돌려준다. 사용자 확인은 그 ID에 결합되며 제출 시 새 payload를 받지 않는다.
4. 제출은 명시적인 확인이 필요하다. 만료·다른 서비스에서 만든 초안은 거절한다. 전송 직전에 가용성을 다시 확인한다. 재확인은 경합에 대한 원자적 보장을 대신하지 않는다.
5. 동일 연결/계정/자산/시작/종료의 중복은 제목이나 초안 ID를 바꾸어도 막는다. 비동기 호출 전에 진행 상태를 기록해 더블클릭·동시 제출을 막는다. 같은 제출은 기존 결과를 돌려주거나 진행 중으로 거절하고 재전송하지 않는다.
6. 명령이 시작된 후 timeout·취소·알 수 없는 오류·모호한 응답은 **결과 불확실**이다. 자동 재시도하지 않고 같은 자산/시간을 보류한다. 성공은 transport가 명시적으로 확인한 예약 식별자가 있을 때만 인정한다. 원문 오류·응답을 저장하거나 표시하지 않는다.
7. 실제 transport의 기본 구현은 `contractUnverified`로 실패하고 네트워크·인증·파일 저장을 하지 않는다. 생성의 모의 경로만 준비한다. 변경·취소·반복·참석자 초대는 미구현이다.

중복 장부는 프로세스 내 메모리만 사용한다. 앱 재시작·여러 장치·다중 프로세스에서 exactly-once를 보장하지 않는다.
실제 모드를 만들기 전에는 서버 idempotency 보장 또는 내구성 있는 요청 장부와 readback 대사, 자산 잠금/경합 계약이 필요하다.
연결/계정 변경·로그아웃·비활성화는 나중의 호스트에서 초안과 확인을 무효화하고, 진행 중 불확실 요청의 장부는 유지해야 한다.

## 사용자 확인 화면 초안 · 제안, 가상 데이터

```text
자산 예약 확인                         모의 실행 · 실제 예약 불가
계정       테스트 계정 A / 테스트 조직
자산       가상 회의실 A
제목       가상 기획 회의
시간       2026-11-02 14:00–14:30 (Asia/Seoul, UTC+09:00)
작업       새 예약 1건
가용성     조회 시점에 가능 · 확정 아님
확인 유효  초안 생성 후 2분 / 전송 직전 재조회

[초안 닫기]  [내용 수정]  [모의 예약 확인]
```

현재는 네이티브 화면을 설치하거나 앱에 노출하지 않는다. 위 필드에 대응하는 데이터 초안만 구현한다.
내용 수정·계정/자산/시간 변경은 새 초안과 새 확인을 요구한다. Enter나 챗봇의 문장만으로 실행하지 않는다.
중복 제출/확인 대기 중 버튼은 비활성, 만료는 재조회 안내, 충돌은 새 시간 선택을 표시한다.
불확실 결과는 “결과를 확인할 수 없습니다. 다시 제출하지 말고 공식 화면에서 확인하세요.”로 표시하며 재시도 버튼을 두지 않는다.
한영 문구, 키보드 포커스, VoiceOver와 실제 네이티브 화면은 후속 구현·검증 대상이다.

## 실제 연동에 앞서 확인할 조건

- 허가된 테스트 환경에서 자산 목록·가용성 조회·생성·조회/readback·변경·취소의 실제 계약을 확인한다.
- 회사 버전, 자산 권한, 시간대/DST, 승인 필요 여부, 반복/충돌·동시성·성공/실패 응답을 확인한다.
- 정상 로그인·추가 인증·CSRF·동일 출처/redirect 정책을 확인하고 읽기 연결과 쓰기 권한/동의를 분리한다.
- 요청 ID, 중복 억제·불확실 결과 대사·로그아웃/재시작 복구, 최소한의 민감정보 없는 감사 기록을 정의한다.
- 명시적인 사용자 예약 확인 화면과 계정 일치 검사, 내구성 있는 중복 방지 테스트를 완료한다.
- 실제 요청·계정 연결·배포는 별도 요청 범위에서 수행한다. 이번 작업은 어느 것도 실행하지 않는다.

ChatGPT 계정 연동 검토는 [CHATGPT-INTEGRATION.md](CHATGPT-INTEGRATION.md)에 분리한다. ChatGPT 인증은 다우오피스 인증·권한을 대체하지 않는다.

## 검증

새 모듈은 외부 패키지를 설치하지 않고 기존 Swift 도구로 검사할 수 있다.

```sh
bash scripts/check-daouoffice-write.sh
# 기존 SwiftPM 의존성이 준비된 환경에서는 동일 검사 실행 가능
swift run --build-system native DaouOfficeWriteChecks
swift run --build-system native AppPluginChecks
swift run --build-system native AfterSixChecks
HAPPY_LULU_SIGNING_IDENTITY=- bash scripts/build-app.sh
bash -n scripts/check-daouoffice-write.sh scripts/build-app.sh
plutil -lint Resources/Info.plist
git diff --check
```

기존 두 SwiftPM 회귀 명령에는 이 실행 환경의 제약에 맞춰 `--cache-path .build/cache --config-path .build/config --security-path .build/security --disable-sandbox --disable-automatic-resolution --skip-update`를 사용했다. 기존에 준비된 의존성 사본만 사용했고 새 패키지 설치는 하지 않았다. 새 모듈 검사는 위 직접 `swiftc` 스크립트로 실행했다.

실행한 검사는 합성 데이터와 모의 transport만 사용한다. 메모리 중복 장부는 실제 서비스의 원자성·재시작 복구를 증명하지 않는다. `.build/`의 산출물·로그와 개인 상태는 커밋하지 않는다.
