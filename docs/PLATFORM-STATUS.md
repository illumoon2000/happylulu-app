# Mac·Windows 기능 현황과 개발 기준

HappyLulu는 **공통 `main` 하나**를 개발 기준으로 사용합니다. Mac과 Windows에 같은 기능과 근무 계산 규칙을 제공하는 것을 목표로 하며, 플랫폼별 상태와 차이를 아래 한 표에서 관리합니다.

확인일: 2026-10-12. [main 확인 기준](https://github.com/young221718/happylulu-app/tree/564f2199746f3d1fa42339911dd72dff7cdc1335). Mac 1.5.11 build27은 공개 버전입니다. 공개 버전은 [README](../README.md#다운로드), 자동 검사와 미완료 검증은 [플랫폼 검증 기록](PLATFORM-VALIDATION.md)에서 확인합니다.

## 기능 현황

상태는 플랫폼별로 표시합니다. **개발 계획 없음**은 현재 확정된 착수 계획이 없다는 뜻이며 영구적인 미지원 결정은 아닙니다. **개발 중**은 구현 또는 완료 조건에 필요한 검증이 진행 중인 상태입니다. **개발 완료**는 구현과 자동 검사가 `main`에 반영된 상태이며 공개 배포·실기기 검증 완료를 뜻하지는 않습니다.

설정 화면은 Mac의 일반·근무·출근 기록·캘린더·업데이트 사이드바와 Windows의 일반·근무·기록 탭으로 구성됩니다. Windows에는 캘린더·업데이트 항목이 없습니다. Mac 캘린더의 반복 일정은 조회 범위 안의 회차를 개별 일정으로 복사하며 삭제의 자동 반영은 지원하지 않습니다. 상세 제한은 [캘린더 안내](../CALENDAR.md), 업데이트 상태는 [업데이트 안내](../UPDATES.md)와 [검증 기록](../VALIDATION.md)을 확인합니다.

## main 운영과 문서 갱신

1. 작업 브랜치는 최신 `main`에서 시작하고 PR 대상도 `main`으로 통일합니다. 작업이 끝나면 단기 작업 브랜치를 정리합니다.
2. 공통 기능은 양 플랫폼의 요구사항과 기대값을 먼저 맞춥니다. 한쪽 구현만 끝난 상태는 전체 완료로 표시하지 않습니다.
3. 공통 기능·근무 규칙 변경은 Mac과 Windows의 검사·빌드를 모두 확인합니다. 플랫폼 전용 변경은 해당 검사·빌드와 상대 플랫폼 영향 여부를 확인합니다. 공통 [근무 규칙 fixture](../Tests/Shared/attendance.json)와 어느 쪽 Core 변경은 양 플랫폼 CI를 실행하며 그 외 변경은 플랫폼별 경로를 기준으로 실행됩니다([Mac](../.github/workflows/macos.yml), [Windows](../.github/workflows/windows.yml)).
4. 새 공통 기능은 양쪽 구현과 검증이 준비된 뒤 제공하는 것을 원칙으로 합니다. 기존 기능 차이는 이 문서에서 남은 작업으로 추적합니다.
5. 기능을 착수하거나 완료할 때 상태·관련 이슈·남은 검증·확인 기준을 함께 갱신합니다. 출시할 때는 실제 배포 상태도 별도로 갱신합니다.

운영 방향과 기능 동등성 관리: [이슈 #27](https://github.com/young221718/happylulu-app/issues/27).
