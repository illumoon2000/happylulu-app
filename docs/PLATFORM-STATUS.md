# Mac·Windows 기능 현황과 개발 기준

HappyLulu는 **공통 `main` 하나**를 개발 기준으로 사용합니다. Mac과 Windows에 같은 기능과 근무 계산 규칙을 제공하는 것을 목표로 하며, 현재 차이는 아래에서 추적합니다. `dev`, `main-mac`, `main-window`를 상시 개발 브랜치로 두지 않습니다.

확인일: 2026-10-12. 기능 현황은 `main`의 [d6a59f2](https://github.com/young221718/happylulu-app/tree/d6a59f256109d9788f1c92139a60a84e6ad2fadf) 기준입니다. 이번 [양 플랫폼 자동 검사와 남은 검증](PLATFORM-VALIDATION.md)을 별도로 기록했습니다. 공개 버전은 [README](../README.md#다운로드)에서 확인합니다. Mac 1.5.10 build25는 개발 후보이며, 이 문서의 구현 상태가 공개 배포 완료를 뜻하지는 않습니다.

## 상태 기준

| 상태 | 의미 |
| --- | --- |
| **개발 계획 없음** | 현재 확정된 착수 계획이 없습니다. 영구적인 미지원 결정은 아니며, 개발을 시작하면 관련 이슈와 함께 상태를 바꿉니다. |
| **개발 중** | 구현 또는 해당 기능의 완료 조건에 필요한 검증이 진행 중입니다. 남은 작업을 함께 적습니다. |
| **개발 완료** | 해당 플랫폼의 구현과 자동 검사가 `main`에 반영됐습니다. 공개 배포와 실제 기기 검증 여부는 별도로 확인합니다. |

상태는 플랫폼별로 기록합니다. 한쪽만 완료한 기능을 양 플랫폼 공통 기능의 완료로 처리하지 않습니다. 실제 기기에서의 공통 확인 사항은 [Mac #4](https://github.com/young221718/happylulu-app/issues/4)와 [Windows #7](https://github.com/young221718/happylulu-app/issues/7)에서 추적합니다.

## 개발 계획 없음

현재 Windows에는 아래 기능이 구현되지 않았으며, 확정된 착수 계획도 없습니다. 기능 동등성을 맞출 때 검토할 차이로 유지합니다.

| 기능 | Mac 상태 | Windows 상태 | 현재 차이 |
| --- | --- | --- | --- |
| 로그인 자동 실행 직후 첫 출근 기록 | 개발 중 | 개발 계획 없음 | Mac은 로그인 항목 실행을 구분하는 코드와 검사가 반영됐지만 실제 부팅·로그인 검증이 남았습니다([#13](https://github.com/young221718/happylulu-app/issues/13)). Windows는 앱 실행 이후의 잠금 해제만 기록합니다. |
| 캘린더 일정으로 오전·오후 반차 인식 | 개발 완료 | 개발 계획 없음 | Mac은 권한 허용 후 일정 제목을 읽고 수동 선택을 우선합니다. Windows는 시간대 판별과 수동 반차 선택만 지원합니다. Mac 실제 권한·일정 판별 확인은 #4에 남아 있습니다. |
| 다우오피스·Google 캘린더 동기화 | 개발 중 | 개발 계획 없음 | Mac에 연결·미리보기·양방향 추가/수정·충돌 처리 코드가 있습니다. Windows에는 캘린더 연결과 동기화가 없습니다. |
| 앱 자체 자동 업데이트 | 개발 중 | 개발 계획 없음 | Mac은 Sparkle 기반입니다. Windows는 앱 종료 후 파일을 직접 교체합니다. |

| 기능 | 플랫폼 | 반영된 내용 | 남은 완료 조건 |

| 로그인 자동 실행 직후 첫 출근 기록 | Mac | 로그인 항목 실행 판별, 첫 기록 보존, 일반 실행·절전 복귀 제외 | 실제 부팅·로그인과 이후 잠금 해제에서 중복 없이 기록되는지 확인([#13](https://github.com/young221718/happylulu-app/issues/13)) |

캘린더의 반복 일정은 조회 범위 안의 회차를 개별 일정으로 복사합니다. 일정 삭제의 자동 반영은 지원하지 않습니다. 상세 제한은 [캘린더 안내](../CALENDAR.md), 업데이트 상태는 [업데이트 안내](../UPDATES.md)와 [검증 기록](../VALIDATION.md)을 확인합니다.

### 플랫폼에 따른 사용 방식 차이

- **시간 표시:** Mac은 메뉴바에 텍스트를 표시합니다. Windows는 트레이 아이콘의 툴팁과 오늘 창에 표시합니다.
- **설정 화면:** Mac은 일반·근무·출근 기록·캘린더·업데이트 사이드바입니다. Windows는 일반·근무·기록 탭이며 캘린더·업데이트 항목은 없습니다.
- **자동 실행:** Mac은 최초 시작 시 로그인 항목 등록을 시도하고 이후 사용자 선택을 보존합니다. Windows는 사용자가 자동 실행을 켤 때 등록합니다.
- **기록 저장:** 각 컴퓨터에 따로 저장하며 Mac·Windows 사이의 출근 기록 동기화는 제공하지 않습니다.

## main 운영과 문서 갱신

1. 작업 브랜치는 최신 `main`에서 시작하고 PR 대상도 `main`으로 통일합니다. 작업이 끝나면 단기 작업 브랜치를 정리합니다.
2. 공통 기능은 양 플랫폼의 요구사항과 기대값을 먼저 맞춥니다. 한쪽 구현만 끝난 상태는 전체 완료로 표시하지 않습니다.
3. 공통 기능·근무 규칙 변경은 Mac과 Windows의 검사·빌드를 모두 확인합니다. 플랫폼 전용 변경은 해당 검사·빌드와 상대 플랫폼 영향 여부를 확인합니다. 현재 CI는 플랫폼별 경로를 기준으로 실행됩니다([Mac](../.github/workflows/macos.yml), [Windows](../.github/workflows/windows.yml)).
4. 새 공통 기능은 양쪽 구현과 검증이 준비된 뒤 제공하는 것을 원칙으로 합니다. 기존 기능 차이는 이 문서에서 남은 작업으로 추적합니다.
5. 기능을 착수하거나 완료할 때 상태·관련 이슈·남은 검증·확인 기준을 함께 갱신합니다. 출시할 때는 실제 배포 상태도 별도로 갱신합니다.

운영 방향과 기능 동등성 관리: [이슈 #27](https://github.com/young221718/happylulu-app/issues/27).
